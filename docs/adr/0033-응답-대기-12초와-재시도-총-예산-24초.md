# 0033. 응답 대기 12초와 재시도 총 예산 24초 (ADR 0004의 값을 대체)

- 상태: 채택 (2026-10-30). Supersedes: [0004](0004-재시도·백오프·총-예산-20초.md)의 값 부분(총 예산 20초, 응답 대기 10초). 백오프 구조는 0004 그대로다.
- 맥락: 사용자 결정(2026-10-30)으로 시간 상한 사슬이 바뀌었다. 응답 생성 5.0초(2.0에서), survey 턴 총 마감 9.0초, gateway 10.5초, 키오스크 대기 12초(10에서). 사슬은 바깥이 안쪽보다 항상 길어야 한다(계약 CONVENTIONS 시간 상한 사슬): 안쪽이 끝나기 전에 바깥이 포기하면 같은 요청이 이중 처리된다. 키오스크 대기 10초는 gateway 10.5초보다 짧아져 사슬이 깨진다.
- 결정: `REQUEST_TIMEOUT_MS = 12_000`, `DEFAULT_RETRY.budgetMs = 24_000`(`src/config.ts`), 링크의 기본 타임아웃도 12초. 다른 값(백오프 기준 0.5초, 상한 5초, 지터)은 그대로.
- 왜: 대기 12초는 사용자 결정이다. 총 예산 24초는 새 대기의 2배로 정했다. 이전 값(20초)이 이전 대기(10초)의 2배였고, 한 번 기다린 뒤 한 번 더 시도할 수 있는 길이라는 성질을 유지하려는 선택이다. 이 2배 비례는 측정이 아니라 이전 선택의 연장이며, 측정하지 않았다. 계약 문서(CONVENTIONS v3.1.1)에는 아직 이전 값(10초, 약 20초)이 적혀 있다: 계약은 헤드의 몫이라 고치지 않았고, 이 영역의 값이 계약 갱신보다 먼저 바뀐다.
- 검토한 대안: (1) 예산 20초 유지 -> 대기 12초 한 번 뒤 남는 8초로는 두 번째 대기가 끝나기 전에 예산이 끊겨 재시도가 사실상 한 번 줄어든다. (2) 예산을 사슬에서 계산 -> 사슬 값(5.0·9.0·10.5)에서 예산을 정하는 식이 계약에 없다.
- 결과: 얻는 것 — 키오스크 대기가 gateway보다 길어져 사슬이 맞는다. 감수하는 것 — 환자가 직원 호출 화면까지 기다리는 최대 시간이 늘어난다(대기 한 번 12초, 예산 24초). 임상 현장에 맞는지는 확인하지 못했다.
- 되돌리는 조건: 사슬 값이 다시 바뀌거나 계약이 다른 예산 규칙을 정하면 새 ADR로 대체한다.
