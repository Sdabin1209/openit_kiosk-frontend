# ADR 0021: 경계 스키마 검증기는 계약 스키마에서 생성해 쓴다

## 상태
채택됨 (2026-10-29, 단위 3, 계약 v2.2.1 D107). ADR 0005(응답 검증을 손으로 쓴다)를 이 경계 스키마 4개에 한해 대체한다. FrontendInput·SessionState 등 응답 검증은 ADR 0005 그대로다.

## 맥락
이 영역이 계약에 올린 경계 스키마 4개(`DeviceConfig`, `KioskStartFragment`, `StaffPushPayload`, `StaticImageInterface`)가 `boundary-contracts`에 승격됐다. 코드는 같은 규칙(토큰·환자 참조 형식, 푸시 본문 키)을 정규식과 `typeof`로 따로 가지고 있었고, 계약과 어긋나도 알 길이 없었다. 계약은 모르는 키를 거부하는데 코드는 무시했다(MANIFEST note).

## 결정
- `scripts/gen-validators.mjs`가 `../boundary-contracts/schemas`의 세 스키마(읽는 쪽)에서 ajv standalone 검증기를 만들어 `api/contract-validators.gen.cjs`에 쓴다. 생성물은 커밋한다. `--check`가 계약과 같은지 `test/contract-validation.test.ts`에서 확인한다.
- `api/contract.ts`가 검증기를 내보낸다. `usableKeys`는 계약을 어긴 객체에서 쓸 수 있는 키를 가린다: 객체 전체를 어긴 것(모르는 키, 객체 아님)은 통째로 쓰지 않고, 한 키만 어긴 것은 그 키만 뺀다.
- `/config.json`은 `DeviceConfig`, 시작 URL 조각은 `KioskStartFragment`, 푸시 본문은 `StaffPushPayload`로 검사한다(`apps/staff/pushbody.ts`). 정규식 상수는 지웠다(R7).
- `StaticImageInterface`는 이 영역이 내는 선언이다. `docs/image-interface.json`(이미지에 싣지 않음)을 시험이 스키마와 Dockerfile·정적 서버 동작에 대조한다.
- 라벨은 시험이 `ImageLabels`로 검사한다. Dockerfile `ARG REVISION` 기본값은 `unknown`이 아니라 `n/a`다(계약: 값 없음은 `n/a` 하나).

## 왜
- 계약 스키마가 정본이고 두 군데에 같은 규칙을 쓰면 어긋난다(워크스페이스 규칙, R7). 검사 모양을 계약 스키마와 같게 하려면 스키마에서 만든 코드가 가장 직접적이다.
- 생성물을 커밋하는 이유: 이미지 빌드 문맥에는 이웃 폴더가 없다. 스키마 복사본이 아니라 스키마에서 만든 코드이고, 최신성 시험이 어긋남을 잡는다. 생성 코드 안에 스키마 JSON(설명 포함)이 들어 있다는 점은 복사본과 닿는다: 번들 크기가 커지는 대가로 받아들였다.
- ajv standalone를 고른 이유: ajv는 이미 devDependency이고(ADR 0005), 컴파일된 함수만 번들하므로 브라우저 런타임에 ajv 컴파일러가 들어가지 않는다(런타임 의존 0 유지). 번들에 들어가는 ajv 조각은 `ucs2length` 하나다.
- 모르는 키 처리: MANIFEST가 "스키마는 모르는 키를 거부한다"고 정했고 note가 그대로 따르라 했다. 객체 전체를 어긴 출처는 쓰는 쪽이 계약과 다르다는 신호라 믿지 않는다(fail closed). 한 키의 형식 오류는 그 키만 버린다: 환자 참조가 틀리면 직원 호출(`subjectInvalid`), 토큰이 틀리면 설정 필요 화면으로 가던 기존 동작을 보존하기 위함이다.
- 푸시 본문이 계약을 어기면 값을 믿지 않고 일반 문구("새 알림이 있습니다")를 보인다: 알림을 버리는 것보다 놓치지 않는 쪽이 낫다.

## 검토한 대안과 버리는 이유
- 손 검증 유지: 어긋남을 못 잡는다.
- 런타임에 ajv로 스키마를 컴파일: 번들에 ajv 컴파일러와 스키마를 싣고, 스키마를 가져오는 경로도 필요하다. 크기·의존이 커진다. 크기는 측정하지 않았다.
- 이미지 빌드에서 생성(계약을 npm 패키지로 설치): 계약은 Python 패키지(태그 설치)이고 Node 설치 경로가 없다. 만들면 새 배포물이 생긴다.

## 결과
- 얻는 것: 계약 예시와 거부 예시가 이 영역 시험의 기대값이 된다. 계약이 바뀌면 `--check`가 실패한다.
- 감수하는 것: 생성물 커밋(스키마 변경 때 `npm run gen-validators`), 번들 크기 증가(빌드 크기만 쟀다: `dist/kiosk.js` 32,165B -> 43,081B, `dist/staff/staff.js` 23,243B -> 30,478B. 성능은 측정하지 않았다). 이웃(deploy, 병원 접수, survey-service)이 실제로 이 모양을 만드는지는 확인하지 못했다(MANIFEST note).

## 되돌리는 조건
계약이 Node 패키지로 검증기를 배포하면 생성물 대신 그것을 쓴다. 기기 인증이 mTLS가 되어 `device_token`·`device`가 스키마에서 사라지면(ADR 0012, 헤드) 생성기를 다시 돌리고 토큰 경로를 지운다.
