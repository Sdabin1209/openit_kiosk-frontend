# ADR 0023: 키오스크 화면은 대화 스레드가 중심이다

## 상태
채택됨 (2026-10-29). ADR 0015(대화 목록은 메모리 전용 별도 컴포넌트)는 그대로이고, 이 ADR은 그 목록을 화면의 중심으로 올린다.

## 맥락
이전 화면은 현재 질문을 큰 글씨 패널(`main#app`)로 보이고, 말풍선 목록(`ol#chat`)은 그 아래 40vh에 붙어 있었으며 첫 대화 전에는 숨겨졌다. 사용자가 "대화 기록이 따로 페이지에 없더라고. 서로 대화 주고 받는 그 대화형 UI가 있기를 바래"라고 요청했다(헤드 전달, 2026-10-29).

## 결정
- 화면은 위에서 아래로 상태 제목(`h1#title`), 대화 스레드(`ol#chat`, 남는 높이를 채우고 스크롤), 아래 고정 입력 영역(`footer#controls`: 입력창, 말하기·직원 부르기·그만하기·연장 버튼, 카운트다운, 안내)이다.
- 시스템(문진) 말과 환자 말이 시간순으로 쌓이고, 새 말이 오면 아래로 스크롤한다. 시작 인사가 첫 말풍선이다(전과 같음).
- 현재 질문 패널은 따로 두지 않는다. 화면 문구(`#text`)는 스레드의 마지막 시스템 말풍선이다. 상태 기계가 만든 문구가 마지막 시스템 말풍선과 같은 글이면 그 말풍선이 현재 질문이고(같은 글을 두 번 그리지 않는다), 다르면(위험 정지 대기, 직원 호출, 실패 안내 등) 스레드 맨 끝에 상태 말풍선(`li.status`)으로 붙는다. 상태 말풍선은 대화 기록(`ChatLog`)에 넣지 않는다: 안내는 대화가 아니라 화면 상태이므로 세션이 끝나면 대화와 함께 사라지고, 같은 안내가 기록에 쌓이지 않는다.
- 새 시스템 말 읽기: 스레드는 `role="log"`, `aria-live="polite"`, `aria-relevant="additions"`이고 말풍선을 덧붙이기만 한다(전체를 다시 그리면 낭독기가 지난 말을 되풀이한다). 상태 제목은 별도 `aria-live="polite"`이다. 안내(`#notice`)는 그대로 `role="status"`다.
- 상태 기계, 문구(`messages.ts`), 세션 종료 시 대화 지우기(ADR 0015)는 바꾸지 않았다. `main.ts`는 문구를 화면 밖 버퍼 요소에 쓰고 그릴 때 스레드에 맞춘다.

## 왜
- 사용자 요구이다. 메신저형 대화 화면은 환자가 지금까지 오간 말을 보고 이어 말하기 쉽다고 본 것이다. 고령 환자에게 실제로 더 쉬운지는 측정하지 않았다.
- 현재 질문을 스레드에 합친 것은 같은 글이 두 번 보이면 혼란스럽고(요구 2), 낭독도 두 번 되기 때문이다.
- 버튼 크기·글자 크기는 이전 값을 유지하거나 줄였다: 본문 40px(전 40px), 말풍선 40px(전 32px), 버튼 40px+패딩 24px(전 44px+32px, 최소 높이 88px). 입력 영역이 화면에서 차지하는 높이를 줄이려는 변경이고 터치 목표 크기는 WCAG 2.2 SC 2.5.8(최소 24px)을 크게 웃돈다. 대비는 이전 팔레트를 그대로 썼다(말풍선 `#111` 글자, `#eee`/`#dbe7ff` 배경).

## 보강: 종료와 빈 입력 영역 (같은 날)
- 서버가 문진을 끝낸 경우: `FrontendInput`에는 완료 필드가 없다. 응답 뒤 세션 상태 조회(위험 정지 확인용으로 이미 하던 호출, 새 요청 없음)가 `ENDED`이면 종료 화면으로 가고 마지막 안내 문장을 상태 말풍선으로 보인다. 종료 요청은 다시 보내지 않는다. 이 해석(서버가 문진을 완료하면 상태가 ENDED)은 PUBLIC_API.md 세션 상태 행("직원이 종료하면 ENDED")과 결과의 `ENDED_COMPLETE`에서 추론한 것이고 실제 survey-service의 동작은 확인하지 못했다. 종료되면 ADR 0015에 따라 대화는 지워지고 마무리 안내만 남는다. 모의 서버는 마지막 안내를 낸 뒤 세션을 끝내도록 바꿨다.
- 보이는 입력·버튼·안내가 없으면 아래 영역 자체를 감춘다(위험 정지 대기, 종료, 시작 중). 빈 띠는 고장처럼 보인다.

## 검토한 대안과 버리는 이유
- 현재 질문 패널을 유지하고 스레드를 곁에 두기(이전 방식): 사용자가 대화 기록이 없다고 느꼈다.
- 상태 안내도 `ChatLog`에 넣기: 안내가 반복되면 기록이 쌓이고, 세션 중 상태가 바뀔 때마다 이벤트를 만들어야 한다. ChatLog의 책임(대화)도 흐려진다.
- 스레드를 매번 통째로 다시 그리기: 낭독기가 지난 말까지 다시 읽는다.
- 입력을 스레드 안 마지막 줄에 두기: 터치 키오스크에서 버튼 위치가 흔들려 고령 환자에게 불리하다고 판단했다(측정하지 않았다).

## 결과
- 얻는 것: 대화가 화면 중심에 있다. 지난 말을 다시 볼 수 있다.
- 감수하는 것: 위험 정지·실패 안내가 스레드 끝의 말풍선이라 스레드가 길어지면 안내가 입력 영역 위에서 스크롤 끝에 있다(자동으로 아래로 스크롤한다). 상태 말풍선은 상태가 바뀌면 같은 자리에서 사라지고 새 것으로 바뀐다. 실제 키오스크 단말(해상도, 터치)에서 확인하지 못했다(Playwright 1080x1920 한 해상도만 확인).
- 스크린샷: Playwright 시험이 `e2e-artifacts/kiosk-chat-normal.png`, `kiosk-chat-risk.png`를 남긴다.

## 되돌리는 조건
사용자 시험에서 입력 영역 고정이나 대화형이 오히려 방해가 된다는 결과가 나오면 이전 패널로 되돌린다(ADR 0015의 목록은 그대로 둔다).
