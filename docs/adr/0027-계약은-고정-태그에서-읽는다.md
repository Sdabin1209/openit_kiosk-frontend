# ADR 0027: 시험과 생성물은 계약을 옆 폴더 작업 트리가 아니라 고정한 태그에서 읽는다

## 상태
채택됨 (2026-10-30, check-all 보고).

## 맥락
이 영역의 시험(`test/*.test.ts`)과 `scripts/check-schema.mjs`, `scripts/gen-validators.mjs`가 `../boundary-contracts`의 **현재 작업 트리**를 읽었다. 다른 영역이 먼저 새 계약 태그로 올라가 옆 폴더가 v2.5.1로 앞서 가면, 아직 이전 태그(v2.4.1)에 고정된 이 영역의 생성 검증기 최신성 시험과 `check-schema`가 실패했다(`생성된 검증기가 계약 스키마와 같다(최신성)`; `불일치 Dockerfile BOUNDARY_CONTRACT=v2.4.1 계약=v2.5.1`). 이 영역이 소비하는 계약은 `Dockerfile`의 `ARG BOUNDARY_CONTRACT`로 고정한 태그이지 이웃 폴더의 현재 상태가 아니다(구조 규칙 1).

## 결정
- `scripts/contract-source.mjs`가 고정 태그(Dockerfile ARG)의 내용을 `git -C ../boundary-contracts show <태그>:<경로>`로 읽는다(읽기 전용). 시험과 두 스크립트는 작업 트리 파일 대신 이것을 쓴다.
- 계약 리포의 `schemas/`는 `boundary_contracts/schemas/`로 가는 심볼릭 링크라 git이 링크 너머를 읽지 못한다. 실제 위치로 바꿔 읽는다(`real()`).
- 태그가 옆 리포에 없으면 이유와 함께 실패한다.

## 왜
- 고정한 태그가 이 영역이 소비하는 계약의 정의다. 옆 폴더가 앞서 가도 이 영역의 시험 결과가 바뀌면 다른 영역의 진행에 이 영역이 끌려 다닌다.
- `git show <태그>:경로`는 태그가 가리키는 커밋의 내용을 그대로 준다. 태그로 패키지를 설치하는 방법(`pip install`)은 Node 영역에 맞지 않고 설치 환경을 만든다.

## 검토한 대안과 버리는 이유
- 계약을 이 리포에 복사: 복사본이 어긋난다(워크스페이스 규칙).
- 옆 폴더를 고정 태그로 체크아웃해 두기: 옆 폴더는 다른 소유자의 작업 트리이고 수정 금지다.
- 태그로 설치한 패키지에서 읽기: Python 패키지이고 이 영역은 Node다.

## 결과
- 얻는 것: 옆 폴더가 앞서 있어도(예: 고정 v2.5.0, 옆 폴더 v2.5.1) 시험 253개가 통과한다(그렇게 바꿔 실제로 확인했다). 핀을 올리면 그 태그의 내용으로 생성물이 다시 만들어진다.
- 감수하는 것: 고정 태그가 옆 리포에 있어야 한다(로컬 태그 또는 가져온 태그). 문진 스키마(`../survey-service/schema`)는 이 ADR의 대상이 아니다: Dockerfile은 문진 스키마를 주 버전(`1`)으로만 고정해 정확한 태그가 없어서 옆 폴더의 현재 내용을 그대로 읽는다(`check-schema`와 `test/mock.test.ts`의 StaffSessionView). 같은 종류의 취약점이 남아 있다.

## 되돌리는 조건
계약이 Node 패키지로 배포되면 그 패키지를 고정해 읽는다.
