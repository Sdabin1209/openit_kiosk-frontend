# ADR 0006: 기기 토큰 보관: 메모리 + 설정 파일, 영구 브라우저 저장소 없음

## 상태
**대체됨: ADR 0024(mTLS)가 기기 토큰 보관 결정을 대체한다(2026-10-29). 토큰 경로는 2.x 호환으로만 남는다.** 아래는 당시 기록이다. 채택됨 (2026-10-28 작성. 기존 결정은 코드·docs·git log에서 근거를 찾아 적었고, 근거를 못 찾은 곳은 '근거 기록 없음'이라 표시했다)

## 맥락
PUBLIC_API.md F: 키오스크 기기 토큰을 `Authorization: Bearer`로 `/v1/sessions*`에 보낸다. D88 U8은 기기별 토큰으로 정했다. 감사 P7: 조각 방식은 새로고침하면 사라진다.

## 결정
토큰은 메모리에만 둔다. 받는 길은 (1) 기기 설정 `/config.json`(권장, 정적 서버가 운영이 마운트한 `CONFIG_FILE`을 낸다 — 새로고침해도 다시 읽는다) (2) 시작 URL 조각 `#device=`(시연용, 읽자마자 주소창에서 지움). localStorage·쿠키·IndexedDB에는 저장하지 않는다.

## 왜 (따른 표준과 근거)
- 따른 기준: 비밀은 이미지·리포·로그에 두지 않고 파일로 받는다(워크스페이스 규칙 D84), 쿼리 문자열은 서버 로그에 남으므로 쓰지 않는다.
- 왜 localStorage를 쓰지 않는가: 공유 PC에서는 다음 사용자가 읽을 수 있고, XSS가 나면 유출된다. 기기 전용 브라우저 프로필이 보장될 때만 검토할 수 있고 그 경우에도 위험을 문서화해야 한다. 이 PC에서 그 전제가 맞는지는 모른다.
- 한계(확인 못 함): 서버가 기기별 토큰을 받는지는 survey-service 작업이며 이 영역은 읽지 않았다. 토큰 수명·회전·폐기 절차는 이 영역 문서에 없다. `/config.json`을 그 기기에서만 읽히게 막는 것은 gateway 몫이다.

## 검토한 대안과 버리는 이유
- localStorage에 영구 저장: 위 위험.
- 쿼리 문자열: 로그 유출.
- 서비스 워커/쿠키: 키오스크에 서비스 워커를 두지 않는 결정(ADR 0009)과 충돌, 쿠키는 게이트웨이가 세션 인증을 붙이는 구조와 별개.

## 결과
조각 방식 기기는 새로고침하면 '설정이 필요합니다' 화면이 된다. 운영은 `CONFIG_FILE`을 쓰는 것이 기본이다.

## 되돌리는 조건
기기 전용 프로필·토큰 회전 절차가 정해지면 보관 방식을 재검토한다.
