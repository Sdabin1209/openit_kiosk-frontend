# ADR 0002: 키오스크와 직원 콘솔을 한 리포에 둔다

## 상태
채택됨 (2026-10-28 작성. 기존 결정은 코드·docs·git log에서 근거를 찾아 적었고, 근거를 못 찾은 곳은 '근거 기록 없음'이라 표시했다)

## 맥락
브리프 1·2절이 두 앱과 공개 API 클라이언트 `api/`, 모의 서버를 이 영역 소유로 정했다. 두 앱은 같은 공개 API(I10)와 같은 클라이언트·재시도 정책을 쓴다.

## 결정
한 리포지토리, 한 이미지, 한 정적 서버. 키오스크는 `/`, 직원 콘솔은 `/staff/`. 코드는 `apps/kiosk`, `apps/staff`, 공용 `api/`.

## 왜 (따른 표준과 근거)
- 따른 기준: 브리프 2절(소유 범위), 공개 API 계약 하나에만 의존한다는 D65.
- 근거: 두 앱이 `api/client.ts`, 재시도 정책 `api/retry.ts`, 응답 검사 `api/validate.ts`를 공유한다. 한 곳을 고치면 둘 다 일관된다.
- 한계: 같은 출처·같은 정적 서버라 키오스크 단말에서 `/staff/`가 열릴 수 있다. 직원 경로 차단은 게이트웨이 몫이다(감사 P6, CR-001).

## 검토한 대안과 버리는 이유
- 리포 둘로 분리: 공유 코드(`api/`)를 패키지로 배포해야 하고 두 이미지를 관리해야 한다. 이 규모에서는 이득이 작다고 판단(비교 기록 없음).
- 이미지 둘로 분리하되 리포는 하나: 정적 파일뿐이라 이점 없음. 근거 기록 없음.

## 결과
키오스크 단말이 직원 콘솔 파일을 받을 수 있고(비밀은 없음), 게이트웨이가 접근을 막아야 한다.

## 되돌리는 조건
직원 콘솔을 다른 팀이 맡거나 배포 주기가 달라질 때. `apps/staff`와 `api/staff.ts`를 떼어 내면 된다.
