# ADR 0017: 유휴 초기화에 만료 전 경고와 연장을 둔다

## 상태
채택됨 (2026-10-29, 표준성 점검 #29). ADR 0008의 유휴 초기화(60초)를 보완한다(대체하지 않는다).

## 맥락
말하기 대기·다시 말하기 화면은 60초 입력이 없으면 세션을 끝내고 처음 화면으로 돌아갔다. 경고도 연장 수단도 없었다. 고령 환자를 가정한다(브리프 5절).

## 결정
- 총 제한 60초(D88 U10)는 바꾸지 않는다. 마지막 20초(`IDLE_WARNING_MS`)를 경고 구간으로 쓴다: 40초에 화면 안내("20초 안에 아래 버튼을 누르지 않으면 처음 화면으로 돌아갑니다.")와 "계속하기" 버튼을 보이고 초점을 버튼으로 옮긴다.
- 계속하기를 누르거나 다른 조작을 하면 경고를 거두고 60초를 처음부터 센다. 횟수 제한은 없다.
- 경고 안내는 한 번만 낭독되도록 초 숫자를 매초 바꾸지 않는다.
- 타이머는 한 번에 하나만 걸린다(경고 시점 타이머 -> 만료 타이머). 위험 정지·직원 호출 화면에 타이머가 없는 규칙(K-1)은 그대로다.

## 왜 (따른 표준과 근거)
- 따른 표준: WCAG 2.2 SC 2.2.1 Timing Adjustable(레벨 A)의 "Extend" 조건. 시간이 끝나기 전에 사용자에게 알리고, 간단한 동작으로 연장할 수 있는 시간을 최소 20초 주며, 최소 10번 연장할 수 있게 한다(내용은 기억에 의존, 원문 대조는 헤드가 한다). 시험 `test/idle-warning.test.ts`의 20초·10회는 이 표준 값이다.
- 20초는 표준의 최소치이며 측정하지 않았다. 고령 환자에게 충분한지는 확인하지 못했다. 이 시간 제한이 SC 2.2.1의 예외(필수 제한 등)에 해당하는지는 따로 판단하지 않고 보수적으로 경고를 두었다.

## 검토한 대안과 버리는 이유
- 제한을 끈다: 다음 사람에게 이전 화면이 남는 문제(ADR 0008)가 되살아난다.
- 제한을 10배로 늘린다(SC 2.2.1의 Adjust 조건): 공용 기기에서 화면 잔존 시간이 길어진다.
- 경고 구간을 60초 뒤에 덧붙인다: 총 제한이 80초로 늘어 D88 U10 값이 바뀐다.

## 결과
얻는 것: 표준의 Extend 조건 충족. 감수하는 것: 화면 요소(버튼, 안내)가 하나 늘었다. 브라우저에서 실제 화면과 초점 이동은 확인하지 못했다(jsdom/Playwright 시험은 이 변경용으로 추가하지 않았다). 흐름 시험만 있다.

## 되돌리는 조건
현장 관찰로 경고 시간이 맞지 않다고 확인되거나 헤드가 유휴 정책을 바꿀 때(`IDLE_WARNING_MS`, `IDLE_RESET_MS`).
