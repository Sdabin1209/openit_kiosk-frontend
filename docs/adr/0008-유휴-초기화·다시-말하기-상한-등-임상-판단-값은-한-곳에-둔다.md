# ADR 0008: 유휴 초기화·다시 말하기 상한 등 임상 판단 값은 한 곳에 둔다

## 상태
채택됨 (2026-10-28 작성. 기존 결정은 코드·docs·git log에서 근거를 찾아 적었고, 근거를 못 찾은 곳은 '근거 기록 없음'이라 표시했다)

## 맥락
감사 P3·P4·P9: 방치 시 화면 잔존, 마이크 거부 때 '다시 말씀해 주세요' 무한 반복, 임상 판단 값(신뢰도 하한 등)이 표시 없이 코드에 박혀 있었다.

## 결정
`apps/kiosk/clinical.ts` 한 곳에 `MIN_CONFIDENCE 0.4`, `ENDED_RESET_MS 8초`, `IDLE_RESET_MS 60초`, `MAX_REPEAT 3회`, `LONG_WAIT_NOTICE_MS 5분`, `MAX_INPUT_CHARS 500`을 두고 각각 '사용자 결정 U10, 잠정, H1 실측 뒤 재정'을 주석에 표시한다. 시험(`test/audit.test.ts`)이 표시 존재를 확인한다.

## 왜 (따른 표준과 근거)
- 근거 구분: **D88 U10에서 온 값** — 재질문 상한 3회, 유휴 초기화 60초. **기존 코드의 임의 값** — 신뢰도 0.4(근거 기록 없음, 감사 P9 지적), ENDED 8초(근거 기록 없음). **새로 만든 임의 값** — 5분 대기 안내, 입력 500자(측정 안 함).
- 유휴 초기화는 말하기 대기·다시 말하기·직원 호출 화면에만 적용하고 위험 정지 대기에는 적용하지 않는다(세션을 끝내면 위험 환자의 대기가 사라진다).

## 검토한 대안과 버리는 이유
- 값을 코드 곳곳에 두기(이전): 표시·변경 추적이 안 된다.
- 서버 설정으로 받기: 계약 변경이 필요하고 지금은 불필요. 기기 설정으로 확장할 수 있다(근거 기록 없음).

## 결과
값이 잠정이라 현장 기준이 나오면 바꿔야 한다. 상수 파일 하나만 고친다.

## 되돌리는 조건
H1(24GB) 실측과 임상 검토 뒤.
