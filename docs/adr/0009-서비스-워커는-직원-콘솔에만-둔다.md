# ADR 0009: 서비스 워커는 직원 콘솔에만 둔다

## 상태
채택됨 (2026-10-28 작성. 기존 결정은 코드·docs·git log에서 근거를 찾아 적었고, 근거를 못 찾은 곳은 '근거 기록 없음'이라 표시했다)

## 맥락
직원 콘솔은 웹 푸시를 받아야 하고 푸시는 서비스 워커가 필요하다. 키오스크는 환자 화면이다.

## 결정
`/staff/sw.js`(범위 `/staff/`)만 둔다. 푸시 핸들러만 있고 `fetch` 핸들러·캐시는 없다. 키오스크에는 서비스 워커를 두지 않는다.

## 왜 (따른 표준과 근거)
- 키오스크에 두지 않은 이유(설계 판단, 측정 안 함): 오프라인 캐시를 만들면 낡은 코드가 환자 화면에 남을 수 있다. 정적 서버가 죽어도 이미 열린 화면은 JS가 메모리에 있어 세션을 이어 간다(브라우저 시험으로 확인). 새로고침·최초 로드 실패의 보완은 gateway 몫이다(CR-004).
- 직원 콘솔에서 캐시를 안 두는 이유: 푸시 알림 표시만 필요하고, 알림 데이터는 건강 정보 일부(세션 ID, 종류)라 캐시에 남기지 않는다. 알림 본문이 잠금 화면에 보일 수 있는 점은 감사 P17.
- 한계: 푸시는 보안 출처(HTTPS)가 필요하고 평문 gateway에서는 사실상 불가(감사 R9). 실제 푸시 서비스 경로는 확인하지 못했다.

## 검토한 대안과 버리는 이유
- 키오스크 오프라인 캐시: 낡은 코드 위험, 환자 화면 변경이 즉시 반영되지 않는다.
- 직원 콘솔도 서비스 워커 없이 SSE만: 브라우저가 닫혀 있을 때 알림을 못 받는다.

## 결과
키오스크는 서버나 gateway가 죽은 채 새로고침하면 브라우저 기본 오류 화면이 뜬다.

## 되돌리는 조건
키오스크 새로고침 중 장애가 현장 문제가 되면 gateway 쪽 정적 화면 이중화나 서비스 워커 캐시(버전 정책 포함)를 재검토한다.
