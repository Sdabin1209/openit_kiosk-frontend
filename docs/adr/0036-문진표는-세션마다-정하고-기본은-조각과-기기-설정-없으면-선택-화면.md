# 0036. 문진표는 세션마다 정한다: 시작 조각 > 기기 설정 > 활성 목록(하나면 자동, 둘 이상이면 선택 화면)

- 상태: 채택 (2026-11-03, 사용자 결정, 계약 3.3.0 반영)
- 맥락: 문진표(문항 세트)가 여러 개 함께 활성이 되었다. 세션마다 어느 문진표로 문진할지 정해야 하고, 서버(I10)는 활성 세트가 둘 이상이면 `question_set_id`를 필수로 한다. 키오스크는 환자 앞의 화면이라 값이 없을 때 환자가 고를 수 있어야 한다.
- 결정: 시작 전에 `GET /v1/question-sets`(기기 인증은 `/v1/sessions`와 같음)로 활성 목록을 받는다. 정할 값은 시작 URL 조각 `question_set_id`가 먼저, 없으면 기기 설정 `DeviceConfig.question_set_id`(계약 3.3.0, 환자 참조와 같은 우선순위). 정한 값이 목록에 있으면 `SESSION_START` 본문에 넣어 시작한다. 값이 없고 목록이 하나면 그 하나로 자동 시작, 둘 이상이면 선택 화면(`KioskView.state = CHOOSING`, 제목 버튼 목록)을 보이고 고른 값을 보낸다. 목록이 비면 CALL_STAFF(`NO_QUESTION_SET`, "문진표가 준비되지 않았습니다"). 정한 값이 목록에 없으면 안내(`chooseNotice`) 후 선택 화면. 시작 응답이 400 INVALID_RECORD + `details.reason` `UNKNOWN_QUESTION_SET`/`QUESTION_SET_REQUIRED`이면(목록을 받은 뒤 활성 세트가 바뀜) 목록을 다시 받아 선택 화면으로 간다. 목록 읽기 실패는 기존 재시도 정책으로 재시도하고 소진되면 직원 호출.
- 왜: 순서·건너뛰기는 문진표 자신에서 나오므로 키오스크는 어느 문진표인지만 정하고 문항 구조를 모른다(구조 규칙 4). 우선순위 조각 > 기기 설정은 계약이 정한 것이다(KioskStartFragment 설명). 정한 값이 목록에 없을 때 조용히 다른 문진표로 바꾸지 않는 이유: 기기에 배치된 문진표를 임의로 바꾸면 환자가 의도하지 않은 문진을 받는다. 선택 화면의 글자 크기·터치 크기는 기존 버튼과 같은 CSS를 쓴다(접근성 규칙 유지), 초점은 첫 버튼에 두고, 유휴 경고·만료(WCAG 2.2.1, ADR 0008)를 선택 화면에도 적용한다(만료되면 서버 세션이 없으므로 종료 요청 없이 처음 화면). 목록 확인을 시작 때마다 하는 이유: 활성 세트는 릴리스로 바뀌므로 캐시하면 낡은 값을 보낸다. 값(재시도·대기)은 새로 만든 것이 없고 기존 ADR 0035를 따른다.
- 검토한 대안: (1) 목록 없이 정한 값만 보내고 서버 오류로 처리 -> 값이 없을 때 환자가 고를 수 없다. (2) 목록이 하나여도 항상 선택 화면 -> 환자에게 의미 없는 한 번의 터치. (3) 기기 설정 값이 목록에 없으면 첫 문진표로 대체 -> 위 이유로 거부. (4) 목록을 앱 시작 때 한 번 받아 캐시 -> 낡은 값.
- 결과: 얻는 것 — 여러 문진표를 세션마다 고를 수 있고, 하나뿐이면 환자 조작이 늘지 않는다. 감수하는 것 — 시작마다 요청이 한 번 늘어난다(측정하지 않았다). 선택 화면 문구는 임시 UI 문구(임상 검토 전)다.
- 되돌리는 조건: 서버가 세션 시작에서 문진표를 자동 배정하게 계약이 바뀌면 새 ADR로 대체한다.
