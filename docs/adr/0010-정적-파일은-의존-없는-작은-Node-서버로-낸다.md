# ADR 0010: 정적 파일은 의존 없는 작은 Node 서버로 낸다

## 상태
채택됨 (2026-10-28 작성. 기존 결정은 코드·docs·git log에서 근거를 찾아 적었고, 근거를 못 찾은 곳은 '근거 기록 없음'이라 표시했다)

## 맥락
이미지는 정적 빌드를 담고 `/healthz`(살아 있음), `/readyz`(index.html 존재)를 제공해야 한다(워크스페이스 D22). 서비스 API는 없다.

## 결정
`server/static.mjs`(Node 표준 라이브러리만). 보안 헤더(CSP, nosniff, Referrer-Policy, Permissions-Policy, COOP/CORP)를 모든 응답에 붙이고, 경로 탈출을 막고, `CONFIG_FILE`이 있으면 `/config.json`으로 낸다. `/healthz`·`/readyz`는 로그에 남기지 않는다. 컨테이너는 non-root(`USER node`).

## 왜 (따른 표준과 근거)
- 따른 기준: 이미지 규약(non-root, healthz/readyz, 로그 stdout, 환경 변수 설정), 의존 최소.
- 근거: 파일이 몇 개뿐이고 런타임 의존이 0이다. nginx/Caddy 등을 이미지에 넣으면 설정·공급망이 늘어난다. 근거 기록 없음: nginx 등을 직접 비교한 기록은 없다.
- 한계: HSTS·TLS는 gateway 몫이다(감사 B8). `node:24-alpine` 태그만 고정되어 있고 digest·SBOM·스캔은 없다(감사 P8).

## 검토한 대안과 버리는 이유
- nginx/Caddy 이미지: 설정 파일·헤더 규칙을 따로 관리해야 한다(비교 기록 없음).
- gateway가 정적 파일을 직접 서빙: deploy 구조 결정이며 이 영역에서 정하지 않는다(CR-001).

## 결과
서버 코드를 직접 유지해야 한다(작다). `/v1`은 처리하지 않는다.

## 되돌리는 조건
파일 수가 늘거나 압축·캐시 정책이 필요해질 때.
