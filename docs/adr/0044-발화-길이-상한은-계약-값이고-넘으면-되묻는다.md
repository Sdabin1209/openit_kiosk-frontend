# ADR 0044: 발화 길이 상한은 계약 값이고, 넘으면 자르지 않고 되묻는다

## 상태
채택됨 (2026-11-08, 계약 v5.0.0).

## 맥락
이 영역은 화면 입력을 `MAX_INPUT_CHARS = 500`(임의 값)으로 `input.maxLength`와 `kiosk_flow.hear`에서 조용히 잘랐다. 계약 `UtteranceBody.utterance`의 상한은 1000자라 값이 두 개였고(D117 위반), 환자 발화가 알림 없이 사라졌다(임상 내용 손실).

## 결정
- 길이·공백 규칙은 내부 스키마 `UtteranceText`(계약 `UtteranceBody.utterance`를 `$ref`)의 생성 검증기가 판정한다. 코드에 숫자를 두지 않는다.
- 상한을 넘으면 서버로 보내지 않고 `REPEAT_PROMPT`(`repeatReason=TOO_LONG`)에서 "말씀이 너무 길어요" 안내 후 다시 받는다. 화면 입력은 지우지 않아 환자가 줄일 수 있다.
- `input.maxLength`는 두지 않는다(화면이 조용히 막지 않는다).
- 연달아 되묻기는 기존 `MAX_REPEAT`(3)에 합산되어 넘으면 직원 호출로 간다.

## 왜
- 같은 뜻의 값은 한 번만(D117), 계약이 정본. 조용한 실패 금지: 사용자가 모르는 채 내용이 사라지면 안 된다.
- 길이 단위: JSON Schema `maxLength`는 코드 포인트 수이고 `Array.from`과 같은 단위다.

## 검토한 대안과 버리는 이유
- 화면 한도 500 유지 + 근거 ADR: 계약보다 좁은 이유가 임의 값뿐이라 근거가 없다.
- 계약 상한(1000)까지 자르기: 여전히 말없이 자른다.
- `input.maxLength=1000`을 코드 상수로: 계약 값의 사본이 된다.

## 결과
- 얻는 것: 값 한 곳, 손실 없음. 감수하는 것: 매우 긴 발화는 한 번 더 말해야 한다.

## 되돌리는 조건
계약이 상한을 바꾸면 생성만 다시 한다(코드 변경 없음). 임상 검토가 안내 문구를 바꾸면 `patient_copy.ts`만 고친다.
