# 0038. 문진표 선택 규칙 정정: 목록에 없는 배치 값은 보내지 않고, 빈 목록은 없다 (0036의 일부를 대체)

- 상태: 채택 (2026-11-04, 계약 3.4.4 PUBLIC_API I절). Supersedes: [0036](0036-문진표는-세션마다-정하고-기본은-조각과-기기-설정-없으면-선택-화면.md)의 "정한 값이 목록에 없으면 안내 후 선택 화면", "목록이 비면 직원 호출", "400 reason이면 목록을 다시 받아 선택 화면" 부분. 나머지(조각 > 기기 설정 > 목록, 하나면 자동, 둘 이상이면 선택 화면)는 유지.
- 맥락: 3.4.4가 I절을 고쳤다. 정한 값이 목록에 없으면 그 값을 보내지 않고 정한 값이 없는 경우와 같이 한다(하나면 그것, 둘 이상이면 선택 화면). 400 `UNKNOWN_QUESTION_SET`을 받으면 목록을 다시 받아 같은 처리를 한 번만 한다(같은 값으로 다시 보내지 않는다). 활성 릴리스가 없으면 목록은 빈 200이 아니라 503 `NO_ACTIVE_RELEASE` + `Retry-After`다.
- 결정: 목록에 없는 배치 값은 조용히 무시하고 안내 문구 없이 같은 규칙으로 진행한다. `UNKNOWN_QUESTION_SET`은 시작 한 번에 한 번만 목록을 다시 받고, 또 거절되면 직원 호출이다. `QUESTION_SET_REQUIRED`는 재시도 없이 직원 호출이다(목록을 받은 뒤 시작했는데 필수라는 것은 계약 위반 상황). 빈 목록(200, 계약 위반)은 시작하지 않고 직원 호출이다. 503 `NO_ACTIVE_RELEASE`는 ADR 0037의 시작 불가 안내.
- 왜: 계약이 정했다. 배치 값은 접수·기기 배치가 정하므로 환자에게 "정해 둔 값을 못 쓴다"는 안내를 보이는 것은 환자가 할 수 있는 일이 아니다. 같은 값으로 재시도하지 않는 이유는 같은 요청이 같은 결과이기 때문이다.
- 검토한 대안: 안내 문구를 유지 -> 계약에 없는 동작이라 지운다.
- 결과: 얻는 것 - 계약과 같은 규칙. 감수하는 것 - 기기에 배치한 문진표가 비활성이어도 화면에서 알아채기 어렵다(하나면 다른 문진표로 시작한다).
- 되돌리는 조건: I절이 바뀌면 새 ADR로 대체한다.
