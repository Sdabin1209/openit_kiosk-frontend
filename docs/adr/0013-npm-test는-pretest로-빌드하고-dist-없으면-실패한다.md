# ADR 0013: npm test는 pretest로 먼저 빌드하고, dist가 없으면 시험이 실패한다

## 상태
채택됨 (2026-10-28).

## 맥락
`test/static.test.ts`의 "빌드 산출물에 토큰과 외부 URL이 없다"는 `dist/`(esbuild 번들)를 검사한다. 시험이 `dist` 없을 때 건너뛰게 되어 있어, 새 clone에서 `npm ci && npm test`는 건너뜀 1건으로 통과하고 `npm run build` 뒤에야 건너뜀 0이 됐다. 번들에 토큰이나 외부 URL이 박혔는지 검사하는 보안 시험이 조용히 빠진 채 초록으로 보일 수 있다.

## 결정
1. `package.json`에 `"pretest": "npm run build"`를 둔다. `npm test`는 항상 새로 빌드한 `dist`를 검사한다.
2. 해당 시험은 `dist`가 없으면 건너뛰지 않고 실패한다(`node --test`를 직접 돌린 경우 포함).

## 왜 (따른 표준과 근거)
- 표준: npm의 `pre<script>` 수명주기 훅은 선행 준비 단계를 두는 관용 방식이다. `npm test` 한 명령으로 시험이 끝나므로 README 절차가 단순하다.
- 보안 시험을 건너뜀으로 둘 수 없다. 건너뜀은 통과로 집계되어 CI에서 드러나지 않는다.
- 낡은 `dist`를 검사하는 위험도 없앤다(build.mjs는 dist를 지우고 다시 만든다).

## 검토한 대안과 버리는 이유
- README에 `npm ci && npm run build && npm test`만 명시: 절차를 어기면 다시 조용히 건너뛴다. 사람의 기억에 의존한다.
- 시험이 직접 빌드: 시험이 부수 효과를 가지며 시험 시간이 모호해진다.
- 건너뜀 유지 + CI에서 건너뜀 0 확인: 별도 도구가 필요하고 로컬은 여전히 구멍이다.

## 결과
얻는 것: 건너뜀 0이 보장된다. 감수: `npm test`마다 esbuild 번들이 돈다(측정하지 않았다; 작은 번들이라 짧다고 보이나 확인한 값은 아니다).

## 되돌리는 조건
빌드가 시험 주기를 눈에 띄게 늦추면 시험용 빌드를 분리하는 새 ADR로 대체한다.
