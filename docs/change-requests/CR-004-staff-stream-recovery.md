# CR-004 (대상: 헤드 -> survey-service, deploy) 직원 알림 스트림 복구에 필요한 서버·gateway 쪽 사실

작성: kiosk-frontend. 이 영역에서 한 것은 `docs/design.md` 3절 "직원 콘솔 연결 상태"에 있다. 아래는 이 영역 안에서 할 수 없는 것이다.

1. **하트비트 형식 확정(survey-service).** 직원 콘솔은 브라우저 `EventSource`를 쓰므로 `: ping` 같은 주석 줄을 볼 수 없어 서버가 조용히 멈춘 스트림을 감지하지 못한다. 하트비트를 `event: ping`(또는 `heartbeat`) 이름 있는 이벤트로 주면 콘솔이 "N초 동안 아무것도 없으면 끊김"으로 처리할 수 있다. 현재는 15초 주기 목록 재읽기로 대신한다. 서버가 실제로 무엇을 보내는지는 읽지 못했다.
2. **스트림 재연결 시 `Last-Event-ID`(survey-service).** 콘솔은 HTTP 오류 뒤 새 연결을 열기 때문에 `Last-Event-ID`를 보내지 못한다. 그래서 놓친 알림을 목록 API로 보충한다. 목록 API가 `OPEN`/`RESOLVED` 전부를 커서로 돌려준다는 전제다(모의 서버는 그렇게 동작, 실제 서버는 확인하지 못함).
3. **gateway 상류 장애 응답(deploy).** `/v1/staff/alerts/stream`이 상류 재시작 중 502/503/504(JSON, `Retry-After`)로 즉시 끊기는지, 연결 채로 멈추는지 알 수 없다. FAULT_POLICY 원칙 6대로 즉시 503/504면 콘솔은 백오프로 재연결한다.
4. **정적 화면 장애(A3, deploy).** 키오스크·직원 콘솔 최초 로드가 실패하면 브라우저 기본 오류 화면이 보인다. 이 리포지토리 안에서는 고칠 수 없다(서비스 워커 오프라인 화면은 환자 화면 캐시 정책이라 보류). 이미 로드된 앱은 정적 서버 장애와 무관하다(추정, 미확인).
