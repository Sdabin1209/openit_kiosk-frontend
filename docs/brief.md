# 영역 브리프: 키오스크 프론트 (kiosk-frontend)

> **성격(D65).** 이 영역은 **떼어 낼 수 있는 가장자리 영역**이다. 실제 프론트팀이 맡게 되면 이 리포지토리를 통째로 그 팀의 것으로 바꾸거나 버리고, 나머지 시스템은 그대로 둔다. 그래서 의존은 **공개 API 계약 하나뿐**이다. 지금은 우리가 대략적으로 만드는 **참고 구현**이다(완성도보다 계약대로 동작하는 것과 분리 가능성이 목표).
> **읽기.** `../boundary-contracts`(`PUBLIC_API.md`, 문진 스키마 JSON)는 읽기 전용이다. 다른 영역 리포지토리는 읽지 않는다. 이 영역은 Node/TypeScript이며 Python 규칙(venv, pip)은 해당하지 않는다. 나머지 공통 규칙(커밋, 변경 요청, 컨테이너 규약, 한국어)은 같다.

## 1. 목적과 범위

- 목적: 환자가 키오스크에서 음성으로 문진하는 웹 화면(키오스크 앱)과, 위험 신호로 멈춘 세션을 풀거나 종료하는 직원용 웹 화면(직원 콘솔 앱)을 대략적으로 만든다.
- 하는 일: 
  - **키오스크 앱**: 세션 시작, 음성 입력(STT)을 텍스트로 바꿔 발화로 전송, 응답 문장 표시(읽어 주기는 선택), 세션 종료. 재시도·직원 호출 화면 처리.
  - **직원 콘솔 앱**: 알림 목록, 실시간 구독(SSE), 웹 푸시 구독 등록, 개입 결정(재개/종료).
- 하지 않는 일: 문진 로직, 문항 판단, 모델 호출, 데이터 저장(환자 발화를 브라우저에 저장하지 않는다). 서버 토큰을 갖지 않는다. STT 서비스 자체를 만들지 않는다(브라우저 기능이나 외부 제공자를 어댑터 뒤에 둔다).

## 2. 소유하는 것

- 소유: 이 리포지토리의 두 웹 앱, 공개 API 클라이언트 모듈(`api/`), 공개 API의 **모의 서버**(`mock-server/`).
- 모의 서버: `../boundary-contracts/PUBLIC_API.md`와 스키마를 읽어 만든다. 다른 영역 코드를 가져오지 않고 혼자 시험·시연할 수 있게 하는 대역이다(이웃 영역의 메모리 구현에 해당). 위험 정지, 전달 실패, 지연, 오류 응답을 시나리오로 낼 수 있어야 한다.
- 제공하는 서비스 API: 없음. 정적 파일을 내는 컨테이너(`/healthz`)뿐이다.
- 산출물: 정적 빌드를 담은 이미지(non-root, 로그는 표준 출력, 라벨 `io.openit.*` 필수 6개 중 해당하는 것과 `io.openit.contracts.boundary`, 앱 버전).

## 3. 소비하는 것

- 소비하는 계약: **I10 공개 API**(`PUBLIC_API.md`): 세션 시작·발화·종료, 직원 콘솔(알림 목록, SSE, 푸시 구독, 개입 결정). 응답 스키마 `FrontendInput`, `TurnFailureSignal`(문진 스키마).
- 다른 영역의 SDK나 코드는 쓰지 않는다. 서버 주소는 배포 환경이 정하는 같은 출처의 `/v1`이다.
- 타입은 문진 스키마 JSON(`../survey-service/schema/schemas`)에서 생성하거나 손으로 쓰되, 복사한 스키마를 리포지토리에 두지 않는다(생성 스크립트가 읽어 온다).

## 4. 상위 수용 기준

- 모의 서버만으로 두 앱의 전체 흐름이 시연되고 자동 시험이 통과한다.
- 공개 API 규칙을 지킨다: 세션 ID는 프론트가 발급(1~64자 영문·숫자·`-_`), 턴마다 고유 `turn_id`, 한 세션의 요청은 하나씩 순서대로, 응답이 없으면(10초) 같은 `turn_id`로 재시도하고, 일시 장애(429·502·503·504·네트워크 오류·무응답)는 지수 백오프로 총 재시도 예산(기본 20초, 잠정) 안에서 재시도하며 예산을 넘으면 직원 호출 화면(FAULT_POLICY 원칙 7; 이전 "3회 실패"를 대체).
- `turn_failure_signal`이 있으면 처리한다: `staff_alert = DELIVERY_FAILED`이면 **직원을 직접 부르는 화면**을 보인다. `write_committed = NOT_COMMITTED`이면 환자에게 다시 말해 달라고 안내한다.
- STT 결과가 비었거나 신뢰할 수 없으면 서버로 보내지 않고 "다시 말씀해 주세요"를 안내한다. STT를 쓸 수 없으면 화면 입력으로 폴백한다.
- 환자 발화나 응답을 `localStorage`, 쿠키, 콘솔 로그, 외부 분석 서비스에 남기지 않는다. 음성 인식은 기기 안에서만 한다(D88 U3, 기본). 외부 STT 제공자로의 전송은 기기 설정으로만 허용한다. 외부 CDN을 쓰지 않는다(의존은 잠금 파일로 고정, 이미지에 포함).
- 서버 토큰이 코드, 빌드 산출물, 브라우저에 들어가지 않는다. 인증은 배포의 게이트웨이가 요청에 붙인다(deploy와 협의 사항은 변경 요청으로).
- 직원 콘솔은 개입 결정을 보내기 전에 확인을 받고, 같은 알림에 대한 중복 클릭이 같은 `turn_id`로 가서 한 번만 처리되게 한다.
- 이미지가 빌드되고 `/healthz`에 응답한다(스모크 스크립트, 고정 포트 금지).

## 5. 비기능 요구

- 키오스크 앱: 큰 글자, 한 화면에 한 가지 행동, 음성 우선. 고령 환자를 가정한다. 한국어. 접근성(대비, 포커스 순서)을 기본으로 한다.
- 직원 콘솔: 데스크톱·태블릿 브라우저. 새 알림이 오면 화면 상단과 푸시로 알린다.
- 지연: 한 턴의 화면 갱신이 응답 후 즉시. 네트워크 단절 시 상태를 보이고 복구되면 이어간다.
- 번들은 작게, 오프라인 폰트 포함.

## 6. 건드리면 안 되는 경계

- 공개 API 외의 서버 경로를 호출하지 않는다. 문진 스키마나 `boundary-contracts`를 수정하지 않는다(변경 요청).
- 환자 개인정보(이름, 환자 번호)를 요구하거나 보내지 않는다.

## 7. 이 영역에 해당하는 열린 결정

- STT 제공 방식(브라우저 내장 vs 외부 제공자): 미정. 어댑터 인터페이스를 두고 기본은 브라우저의 Web Speech API로 시작한다. 한국어 정확도는 확인하지 못한 상태이므로 바뀔 수 있다.
- 직원 콘솔의 로그인 방식: 미정(게이트웨이 인증을 가정). 
- 읽어 주기(TTS) 여부: 선택 기능.
- 기술 스택: TypeScript와 빌드 도구(Vite 등)를 권장하나 영역이 정한다. 의존은 최소로 한다.
